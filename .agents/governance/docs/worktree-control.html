Worktree Control Model / 工作树控制关系

这里区分四个经常被混为一谈的对象：human、main-agent、worktree 和 worktree-agent。Agent runtime 只负责实例化这些 agent 角色；Git worktree 提供隔离， 控制权决定谁可以向其中的 agent 发出写入指令。

创建者不等于控制者

Human 和 main-agent 都可以创建 worktree，之后仍可把控制权交给另一方。

控制者不等于集成者

Human 可以直连 worktree-agent，同时让 main-agent 保持最终集成责任。

模式属于 worktree

同一 repo 可以同时存在 mediated、direct 和等待交接的多个工作树。

Four Repository Entities / 四类仓库对象

持久性、权限和职责不同，也不能把 agent runtime、agent session 与 Git worktree 当成同一个东西。

Creation owner / 创建者

只负责建立 worktree。Human 或 main-agent 都可以承担。

Active controller / 当前控制者

唯一可以向该 worktree-agent 发出写入指令的一方。

Integration owner / 集成者

检查 commits 和 diff、决定合并顺序并运行最终验证；默认是 main-agent。

控制变化是 checkpoint transition，不是重新创建 worktree，也不是强制 merge。

Control Transfer / 控制权交接

“随时切换”意味着不重建工作树，但仍要避免两个 agent 同时写同一 checkout。

No concurrent controllers
1 Stop / 停止旧控制

Human 明确通知 outgoing controller 停止发出新写入。

2 Checkpoint / 固化状态

尽量形成 coherent commit，并保留当前 status 与验证结果。

3 Handoff / 补足上下文

只有 Git 无法表达的 next action、风险和 dirty intent 才写入 runtime handoff。

4 Adopt / 新控制者接管

读取 log、status、diff 和 handoff，然后在原 branch 与 worktree 上继续。

! 仅仅打开另一个 agent 会话不会自动完成控制转移；必须先让旧控制者停止写入。

What Persists / 哪些状态应该保存

不建立永久协调数据库。Git 保存事实；模板 handoff 与工具 runtime state 各自桥接临时上下文。

Minimal coordination state

Git: durable facts

  • branch + base/head SHA：工作树的时间线
  • commits + diff：实际完成的修改
  • tests + reports：可验证的功能证据

.agents/runtime/HANDOFF.md: optional context

  • 尚未提交但有意保留的 dirty state
  • 下一步、已运行验证、剩余风险和 integration owner
  • 接管完成后删除或覆盖，不提升为默认项目真相

.omx/ or equivalent: tool state

  • 由具体 runtime 维护的 workflow、hook 或 session 状态
  • 保持 Git ignored，不复制到 repository memory
  • 删除或更换 runtime 不应破坏项目命令与 Git 事实
稳定规则：一个 worktree、一个 active controller、一个明确 integration owner。 详细操作协议：.agents/governance/GUIDE.md
