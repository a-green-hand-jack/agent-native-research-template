Repository Anatomy / 仓库结构图

功能项目保持传统结构；治理被收拢为非运行时 sidecar。两者共享 Git， 但项目代码、命令、实验和证据不依赖治理才能运行。

治理收拢在 sidecar .agents/ 是物理边界，根目录只保留发现适配器。
repo/
项目路径默认属于功能 代码、环境、实验、工具与报告留在生态原生位置。
G

Governance Sidecar

.agents/ 治理 sidecar

可以观察并调用项目接口，但不进入项目运行时、依赖或命令链。

Contained

.agents/governance/

Orientation + rules
  • ANATOMY.md当前边界、拓扑与依赖方向
  • CONTRACT.md项目与 sidecar 的稳定约束
  • GUIDE.md操作、控制转移和集成流程
  • REPO_UNITS.yaml机器可读的所有权真相源
  • tools/repo_check.py结构与非侵入边界检查
  • docs/治理理由、结构地图与演进图

.agents/ 工作表面

Context + procedures
  • .agents/memory/经审查接受的项目事实
  • .agents/skills/项目内可复用的工作技能
  • .agents/runtime/忽略提交的 pad、handoff 与候选记忆

唯一根适配器

Tool discovery only
  • AGENTS.md只负责让 agent 工具发现 sidecar

sidecar 写入边界

Non-invasive
  • read + invoke可读 Git、代码和配置并调用公开命令
  • no runtime hook不注入 import、env、依赖或隐式状态

G → F sidecar 可以观察、调用与验证项目接口

治理通过 Git 和公开命令工作；它不要求项目为 agent 添加运行时入口。

F ↛ G 项目运行时不得依赖 sidecar

移除 .agents/ 后，代码、命令、实验、评估和报告仍应可用。

Worktree Control Plane / 可切换控制模式

控制模式属于每个 worktree；不同模式可以同时存在，创建者不等于永久控制者。

Per worktree · switchable
Mediated / 中介模式 Default
Human ↔ Main Agent ↔ Agent @ worktree A
Direct / 直连模式 Parallel steering
Human ↔ Agent @ worktree B
Human 或 Main Agent 都可以创建或接管 worktree。 checkpoint + optional HANDOFF 后即可切换。 查看完整控制模型
